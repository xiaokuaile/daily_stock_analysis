## 通用配置与认证设置

关闭认证仍须在专用认证设置中提供当前管理员密码；已有登录 Cookie 不能代替复核。这一后端行为和当前中英界面已经由主线实现，本次保持不变。

`PUT /api/v1/system/config`、`POST /api/v1/system/config/import` 及桌面备份导入共享以下约束：

- 不得启用或关闭 `ADMIN_AUTH_ENABLED`；改变认证状态应使用专用认证设置入口。
- 不得通过 `ENV_FILE` 更换活动配置源。
- 认证启用时，不得通过 `DATABASE_PATH` 迁移管理员凭据目录。同目录更换数据库文件名仍可用；这只保存路径，不会迁移数据库。
- 现有认证状态、配置源和受保护凭据目录引用的变量也受保护，包括递归 `${VAR}` 依赖。认证启用时新增数据库路径插值会被拒绝。
- 与当前状态等价的备份项可以导入，保留原有表示；原样的 `${VAR}` 表达式不会被展开覆盖。
- 配置 key 必须是环境变量标识符。普通值不接受能改变物理行边界的分隔符；JSON 中合法的 Unicode 分隔符转义保存并保留 JSON 语义。
- 写盘前检查最终 dotenv 内容，拒绝会通过引号或重新解析改变认证边界的请求。校验失败时整次请求不写盘，也不重载配置。

导入因认证边界变化被拒绝时，应先确认备份来自同一实例。一般配置可以单独导入；如确实需要迁移配置文件或凭据目录，应停止实例、备份 `.env`、数据库以及原目录的 `.admin_password_hash` 和 `.session_secret`，通过离线运维完成迁移，再验证登录。不要通过关闭认证来绕过迁移保护。

这项修复不会自动修改已有个人配置、密码或会话文件，也不会变更现有的调度时间、任务入口、证券账户、交易或通知设置。普通配置保存仍使用当前主线的重载和调度协调逻辑。

## 依赖与维护工作流

保留主线已有 Longbridge 平台/Python 条件、LiteLLM `<1.99.0` 及排除版本，不用旧 requirements 覆盖主线新增依赖。Linux Python 3.11 当前使用 Longbridge 0.2.74，其他条件选择 4.x；条件选择正确不等同于所有操作系统和 glibc 环境都能安装。

PR Review 已是手动触发、仅执行可信默认分支脚本并通过 GitHub API 获取 diff；保留主线新增的事件诊断。每日分析、正常 PR CI、发布和 Secrets 均不在本次修改范围内。

本修复不是全量依赖安全升级。实际验证版本、当前 CI 结论及依赖审计中的剩余问题以对应 PR 的验收记录为准。
